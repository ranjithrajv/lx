# Dependency Decision: octocrab (replaces custom GitHub client)

> **Superseded (2026-09-14):** octocrab was dropped in favour of the
> blocking-`reqwest` GitHub client. That removes the async runtime and
> the `aws-lc-rs`/`cmake` build requirement, leaving every source-provider
> client synchronous. See `CHANGELOG.md`.

**Date:** 2026-08-14
**Context:** `mkdeb` (Rust CLI repackaging GitHub release binaries into multi-arch Debian packages) hand-rolled a ~120-line reqwest-based GitHub API client before checking whether a battle-tested library already existed.
**Decision context:** long-lived / core dependency

## Problem

`mkdeb` needed GitHub release/asset metadata (release by tag, latest release, list releases, repo default branch) plus raw asset downloads. The first draft implemented this as a custom reqwest client — AI-generated code that would require the project to own rate-limit handling, pagination, API-shape churn, and error mapping forever.

## Candidates evaluated

| Library | Score | Notes |
|---------|-------|-------|
| `octocrab` 0.54.1 | 92/100 | The ecosystem-standard GitHub API client (16.5M downloads, ~2M/mo, MIT OR Apache-2.0, released 2026-07-24). Async (tokio), typed models, built-in rate-limit + retry + pagination handling. |
| `github-rs` / misc | n/a | Not mainstream; lower maintenance signal. |
| Custom reqwest client | — | What was already written; 0 deps but owns all API churn. |

## Decision

**Chosen:** `octocrab` v0.54.1
**License:** MIT OR Apache-2.0 (compatible with mkdeb's GPL-3.0-or-later)
**Score:** 92/100 (threshold: 70)

The deciding factor: octocrab is the de facto standard, released weeks ago with 2M monthly downloads, and absorbs rate-limit handling, retries, pagination, and GitHub API evolution — a dependency the project does not have to maintain. The remaining ~20% gap (streaming raw asset/checksum downloads) is covered by a thin wrapper: octocrab for all JSON metadata, a blocking reqwest client retained only for raw binary streaming.

## Integration notes

- **Adapter pattern:** `GitHubClient` wraps `Arc<Octocrab>` + a blocking reqwest client + a single-threaded tokio runtime. octocrab spawns a background tower-buffer worker at build time, so the client must be constructed *inside* `runtime.block_on`.
- **Domain model:** custom `Release`/`Asset` structs kept as the public surface (with `From<octocrab::models::repos::Release>` conversions) so `discovery.rs`, `build.rs`, `validate.rs`, `wizard.rs` did not change.
- **`GITHUB_API_URL` override** preserved via `base_uri`.
- **Signal notes:** no Yellow signals on the swapped-in library; the remaining Yellow in the project is the Docker-based `.deb` builder (see below).
- **Accepted vulnerability (tracked):** `rsa 0.9.10` (RUSTSEC-2023-0071, Marvin attack timing sidechannel, severity 5.9 medium) is pulled transitively by `octocrab` → `jsonwebtoken` `rust_crypto` feature. octocrab hard-requires one JWT crypto feature at compile time; the alternative `jwt-aws-lc-rs` drags in the aws-lc-rs BoringSSL C toolchain (cmake/nasm) — a worse tradeoff for a CLI. The `rsa` path is only reachable through GitHub-App JWT signing, which `mkdeb` never uses (personal-token auth only), so it is dead code. **No fixed upgrade exists upstream.** Monitor at each review; escalate if a fix lands or if App auth is ever added.
- **Deferred:** `debian-packaging` 0.18.0 (MPL-2.0, indygreg/linux-packaging-rs) — pure-Rust `deb::builder::DebBuilder`, control files, changelog, `repository::builder` — is the chosen implementation for the documented phase-2 Docker elimination. Not pulled in now to preserve v1 behavior parity with the debian-multiarch-builder action.
