# Lintian validation via Debian container

**Date:** 2026-08-14
**Context:** The `debian-multiarch-builder` action runs `lintian` against every built `.deb` (its runner image pre-installs lintian). `mkdeb build` had no package-quality gate; the goal was to mirror `run_lintian_check` as a local CLI.

## Decision

Add `--lintian` (plus `--lintian-pedantic`, `--lintian-fail-on-warnings`, `--lintian-suppress`) to `mkdeb build`, and run lintian **inside a Debian container** rather than on the host.

### Why a container (not a host binary)

- The dev host is **Arch-based**; `lintian` is a Debian tool (not in Arch repos) and does not run natively. The task explicitly requires a container or qemu for anything Debian.
- Running in a container keeps the CLI host-agnostic, matching how the whole build path already works (Docker is already a hard dependency of `mkdeb build`).

### Implementation (`src/lintian.rs`)

- On first use, builds a cached image `mkdeb-lintian` (`debian:bookworm` + `apt-get install lintian`, Dockerfile in a tempdir). Subsequent runs `docker image inspect` and reuse the cache.
- Runs `docker run --rm -v <deb>:/tmp/pkg.deb mkdeb-lintian lintian --info [--pedantic] [--suppress-tags ...] /tmp/pkg.deb`.
- Parses `E:`/`W:`/`I:` lines into an `LintianReport` (errors/warnings/info counts).
- `should_fail`: fails on errors always; fails on warnings only when `--lintian-fail-on-warnings` (mirrors action's `fail_on_errors: true`, `fail_on_warnings: false` defaults).
- The action's `lintian.pedantic` and `lintian.suppress_tags` config keys map to CLI flags; the action's `enabled: false` default maps to `--lintian` being opt-in.

## Verification

- `--lintian` on the built `eza_0.23.5-1+bookworm_amd64.deb` correctly reports `2 error(s), 9 warning(s)` (`embedded-library libyaml`, `extended-description-is-empty`, `no-manual-page`, `no-homepage`, etc.) and **fails the build**.
- `--lintian-suppress embedded-library,extended-description-is-empty` clears both errors → build passes (warnings only).
- `--lintian-fail-on-warnings` fails the build when warnings remain.
- Image is built once and cached; subsequent runs reuse it.
- `cargo clippy` clean; 18 tests pass (3 new: severity parsing, non-severity output, fail rules).

## Notes

- Lintian flags are real quality issues in the generated packages (e.g. empty extended description, missing homepage/section/priority) — good candidates for future upstream fixes to the Dockerfile templates.
